# 拆书工作流

> 拆书不是读后感，是用工程视角把一本书的**骨骼**拆出来。原帖的方法内核：**先俯瞰整体（单元→桥段→章），再下探细节（千字级功能）**——只盯一字一段是一叶障目不见泰山。

## 拆书的三重目的

1. **校准审美**：看清头部作品的结构与节奏，给「保留还是舍弃」积累判断力。
2. **供货爽点类型库**：把拆到的「类型→解法→参考作品」归档进 [02-构思/爽点类型库](../02-构思/爽点类型库.md)，下次构思直接取用。
3. **攒人设原型**：记下让你印象深刻的人物及其功能（拆书时顺手做，构思期「合三为一」的原料）。

## 拆什么

- 想写的**题材**的头部作品（学结构与节奏）；
- 你的创意涉及的**元素**的处理者（原帖案例：写谍战权谋就看《琅琊榜》《潜伏》，写驾驭下属就看《万历明君》《绍宋》）；
- 成绩好但你**看不进去**的书（搞清楚为什么留不住你——这往往是毒点的反面教材）。

不用逐字精读。原帖作者自己说：大部分取材都是简单扫一眼，重点看人设与解法。

## 拆解颗粒度（由粗到细）

```
整书 ──→ 单元（6~8万字，40~50个）──→ 桥段（1万字，4章）──→ 章 ──→ 千字（章内上半/下半）
```

- **第一遍（速读）**：只做整书→单元→桥段的切分，搞清骨架和节奏配比（升级:战斗、张弛、地图）。
- **第二遍（精拆）**：进入逐章记录，标注每章在桥段中的功能（代入/拉期待/兑现/承上启下）。
- **千字级**：只对**写得特别好或特别差**的桥段下探，分析章内 5:5、9:1 的比例怎么处理的。

## 操作步骤

1. **建档案**：复制 [拆书模板](拆书模板.md)，填书名、成绩数据（首订/收订比，能看到就填）、题材与卖点。登记进 [拆书登记表](拆书登记表.md)。
2. **速读定骨架**：写出「骨架总览」——单元切分表 + 节奏配比的观察。
3. **逐章拆**：
   - 每章一句话概要（多分号并列几个事件，原帖格式）；
   - 标注桥段定位（这一章在干「代入 / 拉期待 / 兑现 / 承上启下」哪件事）；
   - **点评**随时插（写得好的机制、写砸的地方、读者反应的痕迹）；
   - **如果是我写**：贴原文截图（Obsidian 附件），下面写自己的处理方案——这是拆书最有价值的部分，把「看懂」变成「会写」；
   - 每 5 章左右插一个**小结**：阶段性判断（作者的活儿、节奏、毒点/爽点分布）。
4. **拆完全书提炼**：出场人物表、事件发展结构树、金手指、爽点类型归档（这一步直接喂给爽点类型库）。
5. **归档**：笔记存 `01-拆书/`，解法入库，登记表更新状态。

## 记录规范

- 文件名：`拆书-《书名》.md`（示例见 [拆书示例-护送未亡人](拆书示例-护送未亡人.md)）。
- 截图等附件放 Obsidian 库的统一附件目录，仓库不上传截图（版权与体积考虑）。
- 引用原文点到为止（一两句），点评和「如果是我写」用自己的话。
- 拆书笔记是**给自己看的生产资料**，不是书评，不需要好看，需要**能被未来的你检索和取用**。

## 从拆书到新书（飞轮）

```
拆书 → 解法入爽点类型库 → 构思遐想时取用 → 新书的"圈"更准、更多样
拆书 → 人设原型入小传    → 构思取材时合三为一
拆书 → 结构标尺          → 大纲排布时对照（2:1、张弛、养书）
```

所以**拆书永远不算白做**：哪怕最后没开书，拆到的东西都在库里，等着下一本书。
