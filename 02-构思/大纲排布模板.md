# 大纲排布模板

> 大纲 = 把几十条剧情矛盾用一条合理的线串联排布。原帖强调：这个工作涉及**结构与节奏**，直接决定一本书多少万字会崩、成绩何时停止上涨；同时它「涉及大量的直觉和经验」——本模板的作用就是把那些直觉拆成可核对的检查项。

## 排布表（每本书一份）

```markdown
## 《书名》大纲排布

| 单元 | 矛盾# | 类型 | 地图 | 张/弛 | 氛围 | 主线推进 | 关联设计（养书） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | #3 | 收人 | 京城 | 弛 |  | 立足新朝 | 与#7同事件 |
| 2 | #1 | 杀人 | 京城 | 张 |  | 除掉爪牙 | 承#3 |
| … |  |  |  |  |  |  |  |
```

- **类型**来自[剧情矛盾清单](剧情矛盾清单模板.md)（收人/杀人/副本/陷害）。
- **张/弛**标单元素质；**氛围**记录紧绷程度（谍战高压/日常舒缓/热血…），相邻单元氛围尽量不同。
- **主线推进**：这个单元结束后，主线状态变化一句话（不能写「无」）。
- **关联设计**：相邻单元共享同一事件或同一伏笔回收——读者更愿意一口气追（对付「养书」）。

## 四大检查项（排完必查，来自原帖）

### 1. 升级 : 战斗 ≈ 2 : 1

- 连续四五十章「收人/成长」后，必须安排 20 来章「杀人/打击敌人」。
- 在表上给类型列做视觉标记，连续 3 个以上同型单元 = 警报。

### 2. 张弛交替

- 紧绷连排读者会累，松弛连排读者会无聊。
- 检查「张/弛」列不允许连续 3 个相同。

### 3. 关联性 / 养书设计

- 至少一半的相邻单元有「关联设计」列内容。
- 手段：共享事件（上半/下半场）、伏笔回收、同一组织的连续反应。

### 4. 地图分配

- 每个地图的开/合都要有理由；换地图 = 读者流失点，入场必须带强钩子。
- 检查是否有一条「主场地图」承载主线（原帖案例：全程以京城为主，规避频繁换图）。

## 结构标尺（排布时对照）

| 项 | 标尺 |
| --- | --- |
| 单元体量 | 6~8 万字/个；300 万字 ≈ 40~50 个 |
| 桥段 | 每单元 4~5 个，每个 ≈ 4 章 |
| 开头加速 | 前 10 万字内：10 章一个剧情（正常是 20 章） |
| 主线 boss | 在开头章节就亮出来（终局 boss + 第一卷 boss） |
| 大纲有效期 | 前 100 万字严格执行；之后允许调整、删减、增补 |

## 可视化

排布表定稿后，把单元序列画进 `canvas/大纲结构图模板.canvas`：一行时间轴 + 每单元一张卡（类型着色：收人=绿/杀人=红/副本=黄/陷害=紫），2:1 和张弛的分布一眼可见，比表格更适合整体直觉检查。

## 维护

- 单元写完后回来填「实际章数」，与预计偏差大的记原因（估不准的那种类型，下次多留余量）。
- 100 万字后的调整（删/增/换序）在这里直接改表，并在备注记一笔调整理由——这份「调整日志」就是你自己版本的《一本书是如何诞生的》。
