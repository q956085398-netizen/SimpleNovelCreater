# 剧情矛盾清单模板

> 剧情矛盾 = 构思期的最小剧情包：一对待解决的冲突。原帖的定义：需要被主角营救收服的人、需要被杀死的人、需要互相陷害作对的对手、想写的副本事件。
> **它不是单独一个阶段憋出来的，而是取材期间头脑风暴的副产品**——手边常开这份清单，想到就记一条。
> 数量自检：攒够**几十条**（每条 ≈ 20 章，副本可到 20~40 章）才算撑起一本书。

## 登记表（每本书一个区）

```markdown
## 《书名》剧情矛盾清单

| # | 矛盾一句话 | 类型 | 涉及人物/组织 | 地图 | 预计章数 | 状态 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 |  | 收人 / 杀人 / 副本 / 陷害 |  |  | 20 | 待排 | 灵感来源： |
| 2 |  |  |  |  |  |  |  |
```

## 字段说明

- **类型**：收人（营救/收服，对应「升级」节奏）/ 杀人（打击敌人，对应「战斗」节奏）/ 副本（事件型）/ 陷害（互相算计型）。前两类是排大纲时 2:1 配比的原材料，务必标清。
- **地图**：京城 / 地方 / 敌国 / 世界边缘——大纲排布时做地图分配用。
- **状态**：待排（还没进大纲）/ 已排（标进大纲的单元号）/ 已写 / 砍掉（写了为什么砍，防止下次再捡起来）。
- **矛盾一句话**的写法：谁与谁、因为什么、不可调和在哪。反面：「主角变强」不是矛盾；「XX 需要主角救、但救人就要暴露身份」才是。

## 质量自检（登记时过一遍）

1. **这条矛盾动了至少一条人物关系吗？** 没动任何关系的矛盾是悬浮剧情，要么挂到关系网上，要么降级为某条矛盾里的一个桥段。
2. **读者期待它解决吗？** 矛盾成立的前提是读者在乎其中一方——在乎来自前面铺垫的人物关系。
3. **和已登记的矛盾撞型了吗？** 撞了不是删，是标记「同型不同解」——排大纲时错开，或让两解法形成升级关系。

## 与其他文件的联动

- 立项进大纲：状态改「已排」+ 在 [大纲排布模板](大纲排布模板.md) 对应单元登记编号。
- 新人物出现：回 [人物关系册](人物关系册.md) 补关系。
- 灵感来源值得记：来自哪部作品的哪个桥段（[拆书登记表](../01-拆书/拆书登记表.md) 可回查）。
